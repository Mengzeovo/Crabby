# Loop Skill

Loop 是 Crabby 的统一循环任务系统，支持**交互式轮次任务**（前端驱动，如番茄钟）和**非交互式定时任务**（daemon 驱动，如每日提醒）。

## 触发判断

当用户提到以下关键词时，激活此 Skill：
- `/loop`
- "做 N 轮"、"几轮"、"轮次练习"
- "番茄钟"、"Pomodoro"
- "间隔重复"、"spaced repetition"
- "每轮 X 分钟"、"每 N 分钟提醒我"
- "循环工作流"、"反复练习"

## 两种 Loop 类型

### 交互式 Loop（`interactive=True`，前端驱动）

**判断条件**：用户描述中提到了轮数、每轮时长、倒计时等概念。

```
用户: "帮我做 4 轮番茄钟，每轮 25 分钟专注，5 分钟休息"
  ↓
Crabby 推断: interactive=True
  ↓
展示确认计划
  ↓
调用 loop_start
  ↓
前端开始倒计时
  ↓
每轮结束 → 调用 loop_ask
  ↓
用户提交回答 → 调用 loop_submit
  ↓
所有轮次完成 → 调用 loop_stop
```

**可用工具**：

| 工具 | 说明 |
|---|---|
| `loop_start` | 启动交互式 loop，参数：rounds（总轮数）、duration_minutes（每轮时长）、user_intent（原始意图） |
| `loop_ask` | 通知前端当前轮次结束，显示输入框等待用户 |
| `loop_submit` | 记录用户对本轮的回答，推进到下一轮 |
| `loop_next` | 直接进入下一轮（无需用户输入时使用） |
| `loop_stop` | 主动结束 loop，渲染总结和日记 |

**流程示例**：

```
1. loop_start(rounds=4, duration_minutes=25, user_intent="番茄钟专注练习")
   → 返回: 任务 ID，轮数 x 时长

2. 前端开始倒计时...

3. 第1轮结束，调用 loop_ask(job_id=xxx)
   → 返回: 状态变为 waiting，前端显示输入框

4. 用户输入，frontend 发送 loop_submit
   → 记录回答，进入第2轮

5. 重复步骤 2-4，直到第4轮

6. 所有轮次完成，调用 loop_stop(job_id=xxx)
   → 返回: 渲染总结日记（各轮记录、总时长等）
```

### 非交互式 Loop（`interactive=False`，daemon 驱动）

**判断条件**：用户只描述了定时规则（cron 表达式或自然语言定时描述），没有轮次/倒计时概念。

```
用户: "每天早上9点提醒我写日记"
  ↓
Crabby 推断: interactive=False
  ↓
调用 cron_create(cron="0 9 * * *", prompt="写日记提醒")
```

**可用工具**：

| 工具 | 说明 |
|---|---|
| `cron_create` | 创建非交互式定时任务，参数：cron（表达式）、prompt（任务指令）、recurring（是否循环） |
| `cron_list` | 列出所有 loop 和 cron 任务 |
| `cron_delete` | 删除指定 ID 的任务 |

## 执行步骤

### Step 1 — 解析意图

从用户输入中提取关键参数：

| 参数 | 来源 | 示例 |
|---|---|---|
| 总轮数 | 用户明确说 "4 轮" | 4 |
| 每轮时长 | 用户说 "每轮 25 分钟" | 25 |
| 动作 | 用户描述的循环内容 | "专注工作" |
| 结束动作 | 完成后做什么 | "写总结日记" |

如果参数不完整，使用合理的默认值（如 4 轮 × 25 分钟）并展示给用户确认。

### Step 2 — 前置能力检查

在调用工具之前，验证必要能力：

- **交互式 loop**：`loop_start` 等工具是否已注册；WebSocket 连接是否正常。
- **非交互式 loop**：`croniter` 是否可用；文件写入权限是否正常。

如果缺少必要能力，**直接告知用户**并建议替代方案。

### Step 3 — 向用户展示并确认计划

用结构化格式展示推断结果：

```
Loop 计划
─────────
类型: 交互式 (番茄钟)
轮数: 4 轮
每轮: 25 分钟
总计: 约 100 分钟（专注）+ 休息时间

前端将在每轮结束时显示输入框，等待你分享本轮的感想或收获。
最后一轮结束后会自动渲染总结日记。

确认开始？ (是/否)
```

### Step 4 — 调用工具

根据类型调用对应工具。

### Step 5 — 轮次驱动与收尾

- 交互式：监听前端发送的 `loop_submit` / `loop_next` / `loop_stop` 消息（由 WebSocket 处理）
- 非交互式：等待 cron daemon 自动触发（用户会收到推送通知）

## 注意事项

1. **interactive 由 Crabby 推断，不向用户暴露**：用户不知道也不需要选择 "interactive" 字段
2. **每个会话同一时间只能有一个活跃 loop**：创建新 loop 前检查现有 loop 状态
3. **用户可以提前结束**：通过 `loop_stop` 随时停止
4. **日记自动生成**：`loop_stop` 会渲染包含各轮记录的总结
