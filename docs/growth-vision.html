维度一：用户反馈 / 成长

差距最大 · 优先建设

目标：让 Crabby 成为一个"跨会话的学习档案员"，持续评估用户水平、给出反馈、追踪薄弱点。

当前状态

mentor 人格提供了方法论框架（费曼技巧、Socratic 追问、出题检查理解），Token 用量追踪已实现（单次会话内）。用户水平评估、薄弱点追踪、成长曲线均为空白。

需要补齐的能力

能力 描述 优先级
学习档案（learning_profile）持久化用户的知识掌握状态，包括掌握的知识点、薄弱点、上次练习时间P0
错题本（mistake_log）记录用户理解偏差和正确答案，供后续针对性复习P0
成长可视化跨会话的学习进度图、活跃度曲线、知识覆盖度统计P1
间隔重复引擎基于遗忘曲线自动安排复习时机，由 Cron 触发P1
主动学习推荐根据档案推荐下一个最适合学习的知识点P1
晨间简报（Morning Briefing）每日 Cron 推送：今日复习计划、新知识推荐、习惯打卡状态P2
关键技术改动
  • server/memory/session_store.py：扩展 Session 数据模型，支持 learning_profile 和 mistake_log
  • server/personas/router.py：扩展 Auto router 支持"学习目标路由"
  • server/cron_daemon.py：支持间隔重复触发逻辑
  • 新建 server/tools/learning_profile.py：get_profile、update_profile、get_mistakes、log_mistake 等工具

维度二：深度调研 + 通俗输出

差距中等 · 重点建设

目标：让 Crabby 成为一个普通人信得过的研究员——能深度挖掘信息，也能把结论讲清楚。

当前状态

researcher 人格已有完整方法论（置信度标注、证据分级、反例意识），fetch 工具可抓取网页，obsidian_search 支持 Obsidian 原生 DSL。调研结论不能跨会话记忆，没有结构化报告生成，多形式输出没有开关。

需要补齐的能力

能力描述优先级
调研会话摘要持久化调研结论自动写入 Vault 并能被后续会话读取P0
结构化报告生成基于调研结果生成标准报告（背景/方法/发现/结论/参考）P0
并行多源抓取支持传入 URL 列表并行抓取并聚合分析P1
引用管理结构化存储引用来源，支持生成参考文献列表P1
输出格式开关用户可通过 !tl;dr、!simple、!detail 等指令切换输出深度P1
类比生成保证在 mentor/philosopher prompt 中显式约束类比输出P1
图表渲染支持支持 Mermaid 等图表的渲染管线P2
主动反向验证研究员自动触发"假设检验"——找到可能推翻结论的证据P2
关键技术改动
  • server/tools/fetch.py：扩展为 async 多 URL 抓取
  • server/personas/researcher/PERSONA.md：增强报告格式指导
  • server/memory/conversation_store.py：新增 research_summary 字段
  • server/llm/prompts.py：扩展格式偏好片段
  • obsidian-plugin/src/chat/chatAssistantContent.ts：扩展渲染管线（Mermaid 支持）

维度三：生活管理

差距较小 · 稳步增强

目标：让 Crabby 成为个人效率的核心枢纽——会话、任务、习惯、日程全部可追踪。

当前状态

Session/Conversation 二层模型成熟，Cron daemon 和 task_query 已实现，Obsidian 集成完整。会话标签、习惯追踪专用工具、日历集成为空白。

需要补齐的能力

能力描述优先级
会话标签系统支持给 Session 打标签（项目/主题），按标签过滤和管理P1
习惯追踪工具专用 habit tracker，支持打卡、统计、streaks，可视化坚持天数P1
任务依赖管理Cron 任务支持依赖链，前置任务完成后自动触发后续P1
会话合并将两个相关 Session 的分支合并P2
通用化 task_query不依赖固定命名约定，支持自定义扫描路径和文件模式P2
移动端入口Desktop Pet 向移动端扩展，或 PWA 支持P3
关键技术改动
  • server/memory/session_store.py：Session 标签扩展
  • server/tools/task_query.py：通用化扫描配置
  • server/tools/cron.py：习惯追踪 Cron 模板
  • server/cron_daemon.py：任务依赖队列

核心原则

在实施过程中坚守以下原则：

  • 1
    本地优先，不上云 — 用户数据永远在本地 Vault，不需要账号
  • 2
    人类可读、可编辑、可删除 — 所有自动生成的内容用户都可以修改和删除
  • 3
    不替用户做重大决定 — 涉及写作、删除、整理的操作需要用户确认
  • 4
    不把 Vault 全量塞进模型 — 上下文预算永远有限，按需检索
  • 5
    不自动大规模改写笔记 — AI 的职责是建议，不是执行
