# Crabby 项目能力概览

最后更新：2026-05-12

这份文档是 Crabby 的第一站。它面向第一次了解项目的人：用户、维护者、未来贡献者，以及需要判断这个项目是否值得继续投入的人。

Crabby 是一个围绕本地 Obsidian Vault 构建的 AI 助手。它把 Obsidian 知识库、LLM、多工具调用、MCP、人格工作流、会话分支、定时任务和桌面入口连接成一个本地优先的个人助理系统。

## 一句话

Crabby 让 AI 不再停留在孤立的网页聊天窗口里，而是进入用户自己的 Vault、配置和工作节奏。

## 它解决什么问题

很多人已经把思考、任务、读书笔记、项目资料和日记放在 Obsidian 里，但普通 AI 聊天工具很难真正进入这套知识系统。每次提问都要重新贴背景，模型无法主动搜索旧笔记，也无法和本地工具、提醒、配置、MCP 服务形成稳定工作流。

Crabby 的目标是把这些能力放在同一个本地系统里：

- 在 Obsidian 内直接聊天，不离开知识库。
- 让模型主动搜索 `.md` 和 `.canvas` 内容。
- 用明确的会话和分支保存长期主题。
- 在多个 LLM provider 之间切换。
- 按任务类型切换秘书、档案官、研究员、哲学家和导师等 Persona。
- 通过工具读写 Vault、查询任务、抓取网页、创建定时任务。
- 通过 MCP 接入外部工具生态。
- 用 Electron Desktop Pet 提供 Obsidian 之外的轻量入口。

## 核心组成

Crabby 当前由三部分组成：

- **Obsidian 插件**：主界面。提供聊天、设置、LLM Profile 管理、MCP 配置、会话历史、当前会话树、Obsidian 原生搜索桥和后端生命周期管理。
- **Python FastAPI 后端**：能力中心。负责 LLM 调用、工具循环、MCP、SessionStore、附件、Persona、Skill、Cron、Token/Context 统计和 admin API。
- **Electron Desktop Pet**：桌面伴随入口。复用同一后端，通过 REST/WebSocket 获得聊天、通知和会话恢复能力。

```text
Obsidian 插件                Desktop Pet
聊天 / 设置 / 搜索桥          桌面窗口 / 气泡 / 聊天
        |                          |
        | REST / WebSocket         | REST / WebSocket
        v                          v
Python FastAPI 后端
LLM Profiles / Tools / MCP / Sessions / Personas / Cron
        |
        v
LLM Provider / Ollama / MCP Server / Local Vault
```

## 用户可见能力

### Obsidian 内聊天

Crabby 的主要入口是 Obsidian 聊天视图。它支持：

- 流式 assistant 回复。
- provider 支持时展示 reasoning/thought 内容。
- 展示工具调用开始、结果、警告和完成事件。
- 图片附件，前提是 active profile 支持 vision。
- 上下文窗口占用、当前回合 usage、session 累计 usage。
- 历史 session 恢复。
- 当前 session 的 conversation tree。
- 从已有消息 fork 新分支。

这让用户可以持续推进同一个主题，而不是每次从零描述背景。

### Obsidian 原生搜索

`obsidian_search` 由插件托管，后端 agent 通过桥接调用。它支持接近 Obsidian Search 的语义：

- `.md` 和 `.canvas` 文件。
- 普通词、短语、OR、否定、正则。
- `file`、`path`、`content`、`tag`、`line`、`block`、`section`、`task` 等操作符。
- property 查询。

这项能力让模型可以主动找笔记、Canvas、标签和任务，而不只依赖当前消息里粘贴的文字。

### 会话、分支和历史

Crabby 把 `session` 和 `conversation` 分开：

- `session` 是一个主题容器。
- `conversation` 是 session 下的一条可继续分支。
- 每个请求显式携带 `session_id` 和 `conversation_id`。
- 后端只把当前活跃分支 materialize 成 LLM 历史。
- sibling 分支不会混入当前上下文。
- 后端有 30 分钟 TTL、64 MiB 预算、LRU 驱逐的 active-branch cache。

这适合探索多个方向：主线、备选思路和分叉尝试可以共存，但不会互相污染。

### LLM Profile

LLM Profile 由后端拥有并持久化，插件 UI 负责管理。Profile 可保存：

- provider 和 model。
- API key 和 base URL。
- vision 支持开关。
- thinking / reasoning effort / reasoning split 等 provider 相关设置。

当前内置 provider preset：

- Anthropic
- OpenAI
- Ollama
- DeepSeek
- Qwen / DashScope Coding Plan
- Kimi Code
- MiniMax
- Zhipu / BigModel
- Custom OpenAI-compatible

用户可以在同一个界面管理云端 API、本地 Ollama 和国内 OpenAI-compatible provider。

### Persona

Persona 用来让助手按任务类型切换工作方式。当前内置核心 Persona：

- `secretary`：事务、日程、提醒、待办、项目跟进、习惯追踪。
- `archivist`：笔记整理、知识结构、归档、链接、旧资料召回。
- `researcher`：调研、验证、证据、反例、偏差识别和置信度。
- `philosopher`：价值判断、人生方向、意义、长期目标和取舍。
- `mentor`：讲解、学习路径、复习、练习、出题和反馈。

Persona 模式：

- Auto：LLM router 基于当前和近期上下文自动选择。
- Manual：用户手动指定。
- None：不注入 Persona。

Auto 模式会在置信度足够高时锁定当前 session 的 active persona，避免每一轮都跳变。

### Skill

Skill 是行为指南，不是可执行工具。它通过 `SKILL.md` 描述某类任务的处理方式、触发场景和工具使用边界。

后端从 `skills/` 或 `SKILLS_DIR` 加载 skill。用户可以通过 slash command 强制当前回合使用某个 skill，后端也可以基于用户文本匹配 skill。

### 工具执行

后端有统一 ToolRegistry 和工具循环。模型可调用工具，后端校验输入、检查权限、执行工具、格式化结果，再让模型继续推理。

当前内置工具包括：

- `obsidian_search`：Obsidian 搜索桥。
- `crabby_settings`：插件设置和后端 profile 自管理。
- `read`：读取 Vault 文件。
- `edit`：Vault 内精确文本替换或新建文件。
- `grep` / `glob`：后端侧文件搜索。
- `task_query`：查询 Vault 中的任务。
- `fetch`：网页或内容抓取。
- `bash`：非交互式 shell，启用时可用。
- `cron_create` / `cron_list` / `cron_delete`：定时任务管理。

### MCP

Crabby 支持 MCP server 配置、连接、重载和状态查看：

- 配置文件由 `MCP_CONFIG_FILE` 指定。
- 支持 `${ENV_VAR}` 环境变量插值。
- 支持 `stdio` 和 `sse` transport。
- reload 是事务式的：新 server 全部连接并注册成功后才替换旧工具集。
- 插件设置页可编辑 MCP 配置并触发重载。
- `/admin/mcp/status` 可查看连接状态和工具列表。

### Cron 和后台通知

模型可用 Cron 工具创建未来任务：

- 任务保存到 `<vault>/crabby/data/cron_jobs.json`。
- 支持 5 字段分钟级 cron 和 6 字段 seconds-first cron。
- 后端 daemon 每秒扫描一次。
- 到期任务 FIFO 入队。
- 执行前等待 session activity idle，最长 30 分钟。
- 每次执行使用新的隔离 session。
- 完成摘要写回源 session，并通过 WebSocket 通知在线客户端。

### Desktop Pet

Desktop Pet 是一个 Electron 伴随客户端。它提供宠物窗口、聊天窗口、气泡窗口和设置窗口，连接同一个 FastAPI 后端，并可展示后台通知与恢复 transcript。

## 本地与隐私边界

Crabby 的默认假设是本地个人使用：

- 后端默认绑定本地主机。
- Admin API 需要 admin token。
- API key 存在本地 `.env`。
- sessions、attachments、logs、runtime config 都在本地文件系统。
- Obsidian 搜索通过本机插件桥执行。
- 文件工具做 Vault 路径边界检查。
- session/conversation ID 在文件访问前校验。

需要理解的边界：

- 使用云端 LLM provider 时，用户输入、检索到的上下文和工具结果可能发送给 provider。
- 启用 `bash` 后，模型具备非交互式 shell 能力，只适合可信本地环境。
- `edit`、settings/profile 和 Cron 工具有写入能力，应配合明确用户意图使用。
- MCP server 的能力边界取决于用户配置的外部 server。

## 适合谁

Crabby 适合：

- 以 Obsidian 为长期知识库的人。
- 想让 AI 主动搜索和组织个人笔记的人。
- 需要多 provider、私有部署、可控本地配置的人。
- 想把任务提醒、研究、学习、复盘和知识整理放进一个 assistant 工作流的人。
- 愿意接受“本地自动化工具”安全边界的人。

Crabby 不适合：

- 云端多用户 SaaS 场景。
- 不希望本地运行后端进程的用户。
- 需要开箱即用公共插件商店分发的人。
- 需要内置向量数据库长期记忆的一等实现的人。
- 期待后端二进制自动跨平台交叉编译的人。

## 当前成熟度

已经具备的主干能力：

- Obsidian 插件聊天与设置。
- FastAPI 后端和 REST/WebSocket 协议。
- 本地 managed backend 生命周期。
- LLM Profile 管理和 active profile test。
- 多 provider preset。
- Obsidian 搜索桥和内置工具。
- MCP reload/status。
- Persona、Skill、Prompt 运行时配置。
- session/conversation 分支存储和 active-branch cache。
- Cron 后台任务和通知。
- Desktop Pet 基础客户端。
- 手动发布 zip 打包。

仍然值得继续增强：

- 更完善的写入确认 UI 和工具审计。
- 更成熟的长期记忆、摘要、剪枝和检索缓存。
- 自动发布矩阵、签名和升级流程。
- Desktop Pet 的交互体验。
- 更完整的用户手册、示例工作流和截图。
- 更多 provider 原生能力，例如文件、图像、web search、code interpreter。
