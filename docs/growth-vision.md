# Crabby 产品愿景与成长规划

最后更新：2026-05-15

本文档记录 Crabby 的核心产品愿景、差异化定位、当前能力差距，以及分阶段的演进计划。它是产品方向的源头文档，`docs/execution-plan.md` 负责把这里的计划映射到具体的版本发布节奏，`docs/技术路线.md` 负责把这里的功能需求转译为架构决策。

---

## 愿景

**让每一个普通人都能用上 AI 工具，在工具的帮助下持续提升自己，达到超越平均水平的生产力和认知能力。**

Crabby 不是另一个"和 AI 聊天"的工具。它是一个**个人成长伙伴**：帮助你深度调研你不懂的领域，把复杂知识翻译成你能理解的形式，在实践中给你真实的反馈，并在漫长的学习过程中记住你的每一步脚印。

核心差异化：

1. **能反馈用户、提升用户水平** — 不是给答案，而是引导思考、暴露缺口、追踪进步
2. **深度调研 + 通俗输出** — 能做研究员的工作，也能把结论用普通人能理解的方式讲出来
3. **帮助管理生活** — 把知识转化为行动，把行动沉淀为习惯，把习惯固化为能力

---

## 产品定位

| 维度 | 定位 |
| --- | --- |
| 用户画像 | 有自我提升意愿但缺乏系统性方法的普通人；需要研究新领域但时间有限的知识工作者 |
| 核心矛盾 | AI 能回答问题，但普通人不知道自己的理解是否正确、该从哪里学起、如何把知识用起来 |
| Crabby 的回答 | 研究员（帮你调研）+ 导师（给你反馈）+ 管家（帮你管理）三位一体 |
| 竞争优势 | 本地优先、Vault 集成、长期记忆、可迁移的 LLM Provider |

## 四维能力评估

### 维度一：用户反馈 / 成长（差距最大）

**目标**：让 Crabby 成为一个"跨会话的学习档案员"，持续评估用户水平、给出反馈、追踪薄弱点。

**当前状态**：

- `mentor` 人格提供了方法论框架（费曼技巧、Socratic 追问、出题检查理解）
- Token 用量追踪已实现（单次会话内）
- 用户水平评估、薄弱点追踪、成长曲线均为空白

**需要补齐的能力**：

| 能力 | 描述 | 优先级 |
| --- | --- | --- |
| 学习档案（learning_profile） | 持久化用户的知识掌握状态，包括掌握的知识点、薄弱点、上次练习时间 | P0 |
| 错题本（mistake_log） | 记录用户理解偏差和正确答案，供后续针对性复习 | P0 |
| 成长可视化 | 跨会话的学习进度图、活跃度曲线、知识覆盖度统计 | P1 |
| 间隔重复引擎 | 基于遗忘曲线自动安排复习时机，由 Cron 触发 | P1 |
| 主动学习推荐 | 根据档案推荐下一个最适合学习的知识点 | P1 |
| 晨间简报（Morning Briefing） | 每日 Cron 推送：今日复习计划、新知识推荐、习惯打卡状态 | P2 |

**关键技术改动**：

- `server/memory/session_store.py`：扩展 Session 数据模型，支持 `learning_profile` 和 `mistake_log`
- `server/personas/router.py`：扩展 Auto router 支持"学习目标路由"
- `server/cron_daemon.py`：支持间隔重复触发逻辑
- 新建 `server/tools/learning_profile.py`：`get_profile`、`update_profile`、`get_mistakes`、`log_mistake` 等工具

---

### 维度二：深度调研 + 通俗输出

**目标**：让 Crabby 成为一个普通人信得过的研究员——能深度挖掘信息，也能把结论讲清楚。

**当前状态**：

- `researcher` 人格已有完整方法论（置信度标注、证据分级、反例意识）
- `fetch` 工具可抓取网页
- `obsidian_search` 支持 Obsidian 原生 DSL
- 调研结论不能跨会话记忆，没有结构化报告生成，多形式输出没有开关

**需要补齐的能力**：

| 能力 | 描述 | 优先级 |
| --- | --- | --- |
| 调研会话摘要持久化 | 调研结论自动写入 Vault 并能被后续会话读取 | P0 |
| 结构化报告生成 | 基于调研结果生成标准报告（背景/方法/发现/结论/参考） | P0 |
| 并行多源抓取 | 支持传入 URL 列表并行抓取并聚合分析 | P1 |
| 引用管理 | 结构化存储引用来源，支持生成参考文献列表 | P1 |
| 输出格式开关 | 用户可通过 `!tl;dr`、`!simple`、`!detail` 等指令切换输出深度 | P1 |
| 类比生成保证 | 在 `mentor`/`philosopher` prompt 中显式约束类比输出 | P1 |
| 图表渲染支持 | 支持 Mermaid 等图表的渲染管线 | P2 |
| 主动反向验证 | 研究员自动触发"假设检验"——找到可能推翻结论的证据 | P2 |

**关键技术改动**：

- `server/tools/fetch.py`：扩展为 async 多 URL 抓取
- `server/personas/researcher/PERSONA.md`：增强报告格式指导
- `server/memory/conversation_store.py`：新增 `research_summary` 字段
- `server/llm/prompts.py`：扩展格式偏好片段
- `obsidian-plugin/src/chat/chatAssistantContent.ts`：扩展渲染管线（Mermaid 支持）

### 维度三：生活管理

**目标**：让 Crabby 成为个人效率的核心枢纽——会话、任务、习惯、日程全部可追踪。

**当前状态**：

- Session/Conversation 二层模型成熟
- Loop daemon（重构自 Cron）和 task_query 已实现，支持交互式轮次任务（番茄钟等）和非交互式定时任务
- Obsidian 集成完整
- 会话标签、习惯追踪专用工具、日历集成为空白

**需要补齐的能力**：

| 能力 | 描述 | 优先级 |
| --- | --- | --- |
| 会话标签系统 | 支持给 Session 打标签（项目/主题），按标签过滤和管理 | P1 |
| 习惯追踪工具 | 专用 habit tracker，支持打卡、统计、 streaks，可视化坚持天数 | P1 |
| 任务依赖管理 | Cron 任务支持依赖链，前置任务完成后自动触发后续 | P1 |
| 会话合并 | 将两个相关 Session 的分支合并 | P2 |
| 通用化 task_query | 不依赖固定命名约定，支持自定义扫描路径和文件模式 | P2 |
| 移动端入口 | Desktop Pet 向移动端扩展，或 PWA 支持 | P3 |

**关键技术改动**：

- `server/memory/session_store.py`：Session 标签扩展
- `server/tools/task_query.py`：通用化扫描配置
- `server/loop_models.py` / `server/loop_manager.py`：统一 Loop 数据模型和管理器
- `server/loop_daemon.py`：任务依赖队列（通过 `_job_queue` 支持）
- `server/tools/loop_task.py`：交互式轮次工具（loop_start/loop_ask/loop_submit/loop_next/loop_stop）

### 维度四：产品体验与信任

**目标**：让普通用户第一次使用就能上手，建立信任感。

**需要补齐的能力**：

| 能力 | 描述 | 优先级 |
| --- | --- | --- |
| 首次使用引导（Onboarding） | 插件首次运行时引导用户配置 LLM、介绍核心功能 | P0 |
| 示例工作流 | 内置几个常见场景的示例会话（调研、写日记、习惯追踪） | P1 |
| 截图和视觉引导 | 配合 README 的安装和使用截图 | P1 |
| 进度指示器 | 在聊天中显示"正在搜索…""正在抓取…"等明确的进度反馈 | P1 |
| 错误可解释性 | 失败时给出人类可理解的原因和下一步建议 | P1 |
| 数据导出 | 用户可以导出自己的学习档案和会话记录 | P2 |

## 分阶段实施计划

### Phase 1：打牢基础（0.7）

目标：让 Crabby 具备基本的"学习档案"能力，`mentor` 人格可以跨会话追踪用户表现。

- 学习档案数据模型（Session 扩展）
- 错题本工具和记录逻辑
- `mentor` 人格增强：练习题后自动记录反馈
- 首次使用引导（Onboarding）

### Phase 2：调研能力升级（0.8）

目标：让调研结论可以跨会话复用，输出格式可控制。

- 调研会话摘要持久化
- 结构化报告生成工具
- `fetch` 多 URL 并行抓取
- 输出格式指令（`!tl;dr`、`!detail`）

### Phase 3：生活管理增强（0.9）

目标：让会话和任务管理更系统。

- 会话标签系统
- 习惯追踪 Cron 模板
- 任务扫描通用化
- 晨间简报 Cron

### Phase 4：成长闭环（1.0）

目标：让所有能力串联成完整的个人成长闭环。

- 间隔重复引擎
- 成长可视化面板
- 主动学习推荐
- 引用管理
- 数据导出

## 核心原则

在实施过程中坚守以下原则：

1. **本地优先，不上云**：用户数据永远在本地 Vault，不需要账号
2. **人类可读、可编辑、可删除**：所有自动生成的内容用户都可以修改和删除
3. **不替用户做重大决定**：涉及写作、删除、整理的操作需要用户确认
4. **不把 Vault 全量塞进模型**：上下文预算永远有限，按需检索
5. **不自动大规模改写笔记**：AI 的职责是建议，不是执行
